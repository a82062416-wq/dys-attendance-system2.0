# 首頁共用公告 v1.5.2

管理員原本儲存的公告僅存在本機。此版本沿用首頁入口與設定欄位，另以 Firestore 的單一 `publicAnnouncements/current` 文件發布共用公告。公告為所有網站訪客可讀的公司一般通知，請勿填入同仁個資或機密資訊。

## 操作

使用管理員密碼登入後台 → 系統設定 → 系統公告，填寫內容按「發布給所有同仁」。公告發布權限在背景確認，無須另外登入。一般「儲存設定」不會發布公告；確認失敗時保留內容並提示重試。

開啟最新版的同仁裝置最遲每兩分鐘讀取一次；回到頁面、開啟公告或網路恢復時也會更新。舊頁面須重新開啟一次，不強制重新整理正在打卡的裝置。v1.5.3 將公告入口固定放在打卡時間旁，點開的浮層不推動打卡卡片；未發布／已到期時顯示「目前沒有公告」，讀取失敗且無有效快取時顯示無法載入。離線裝置顯示已快取且未過期的副本，撤回須連線才能接收。無公告時不自動發布測試文字。

## 邊界

- `shared-announcement.js` 獨立載入；公開讀取不需要登入，不讀取名冊、RTDB、Sheets 或打卡佇列。
- 後台登入時以同一組管理員密碼確認公告權限；發布身分使用獨立命名 Firebase app，避免切換打卡身分，登出後失效。
- 伺服器檢查 `announcementAdmins/{uid}.active`，不接受前端管理角色旗標作為授權。僅允許本人讀取自己的角色，禁止前端新增或更改角色。
- 更新以 Firestore `updateTime` 作條件，拒絕覆蓋其他發布者的版本。發布失敗或未確認保留輸入，不自動重送。
- 新增規則必須合併到即時取得的既有規則；不可用測試 fixture 覆蓋其他應用權限。帳號、規則備份、回退用 ruleset 名稱均留在本機受保護資料夾。

## 驗證

`node --test tests/*.test.js functions/test/*.test.js`

`tests/shared_announcement_ui.py`：以本機 HTTP 開啟真正首頁，禁止 Service Worker 與正式資料連線，模擬發布、第二裝置讀取、無權限、衝突、撤回、離線與佇列保護；Chromium / WebKit，320、390、1440 寬。

`tests/ui_smoke.py`：原有手機與桌面打卡、QR、哨點、後台及自主補卡冒煙。

`tests/announcement-emulator/rules.test.js`：僅 demo 專案，驗證公告權限、撤銷與原有集合基本行為；可用 `DYS_RULES_SOURCE` 指向當次合併後規則。請勿載入正式人事資料。

真實帳號測試只讀取公告角色、公告文件並寫入「未發布」狀態；封鎖所有出勤及人事端點。實體 iPhone／舊手機未實測，WebKit 模擬不能當成全機型保證。

## 回退

前端只回退本次公告提交，保留較新的其他提交。回退不刪除 localStorage 或打卡資料。公告停用可先以管理員撤回。必要時使用已備份的 Firestore release ruleset 回復，先確認沒有其他管理者在此之後更新規則；不以過期規則覆蓋他人變更。停用公告帳號只撤銷其公告角色，不關閉原有匿名登入。
